## 未解決の不具合

### Chrome の特定の窓口だけ `file is not a database` になる

2026-08-02 と 2026-08-19 の2回、実機で発生。**原因は分かっていない。**
公開の関門からは外してある。

症状は `SQLite: file is not a database`。Chrome の特定のウィンドウだけで起き、
シークレット・Firefox・Vivaldi では正常。**Ctrl+Shift+R では直らず**、キャッシュ削除で直る。
Vivaldi も Chromium なので**エンジンではなくプロファイル固有**。

潰した容疑者:

| | 判定 |
|---|---|
| R2 の配信 | **無実**（3回とも。HEAD の Content-Length・先頭16バイト・`page_size` を確認） |
| 期間DBの中身 | **無実**（12本ともヘッダ正常・サイズ一致） |
| `accept-ranges` が CORS で公開されていないこと | **原因ではない**（この値は警告を出すだけで取得の仕方を変えない） |
| ブラウザキャッシュ | **無実**。`&retry=1` `&retry=2` も同じく失敗した ＝ URLが違えばキャッシュエントリも別 |
| 2026H2 だけ `Content-Type` が欠けていたこと | **証明できていない**（固定済み。同じURLを別タブから20回引いて20回とも正常だった） |

`search()` は `Promise.all` なので、**1本落ちると検索全体が失敗する**。
対処として `immutable` を外し（再読み込みで治るようになった）、やり直しに `&retry=` を
足してURLを変えた。配信側を壊す再現（`POISON=1`）では自力で復旧するが、
**実機の再発はこれでは救えていない** ＝ 本物の壊れ方を再現できていない。

**再発したら、キャッシュを消す前に見るもの**（消すと次の再発まで何も分からなくなる）:

1. **Console の `<期間> の先頭16バイト`**（`db.ts` の `reportBadHeader()`）。
   `cached`（ブラウザキャッシュ経由）と `network`（`cache: "reload"`）の**両方**が出るので、
   どちらが壊れているか・ゼロ埋めか・HTMLか・別世代のDBかがその場で分かる
2. **`gh run list --workflow=daily.yml`。** 手順13が落ちていれば**サーバ側**。緑なら正常
3. 手元からも同じ検算ができる:
   `python scripts/verify_published.py --base https://db.kokkai-timeline.com`
4. **どの期間が落ちているか**を控える。日次が毎日差し替えるのは当期の1本だけなので、
   そこに寄っているかは意味がある
