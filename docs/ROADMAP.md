## 2. 最大の未検証リスク

> ### ⚠️ sql.js-httpvfs が 350MB のDBで実用速度を出せるか、まだ誰も確かめていない
>
> アーキテクチャ全体がこの前提の上に乗っている。ここが崩れると、
> 「サーバーを持たない」という制約そのものを見直すことになる。
>
> **Phase 1 の最初にプロトタイプで検証する。UIを作り込む前に確かめること。**

検証すべき具体項目:

- 1回の検索で何回の HTTP Range リクエストが発生するか（R2 の Class B 無料枠は月1,000万）
- 初回検索までの待ち時間（DBヘッダとインデックスの読み込み）
- trigram 索引はページが散らばりやすい。ヒット数が多い語（「原子力」など）で最悪ケースを見る
- 年をまたぐ横断検索で、複数DBを順に引いたときの体感速度

**もし実用にならない場合の退避案**（優先順）:

1. 年ではなく**会期ごと**にDBを分割してさらに小さくする
2. 検索対象を直近N年に絞り、過去分は別導線にする
3. 事前計算した転置インデックスを静的JSONで持ち、DBは本文取得だけに使う
4. （最終手段）Cloudflare Workers + D1 を検討。ただし「常時稼働を持たない」制約に触れる

## 4. 未解決の課題

### 4-1. 2文字の検索語が引けない ★最優先

trigram は3文字未満のトークンを作れないため、**「増税」「憲法」「年金」「原発」が
検索結果0件になる**。日本語の政治キーワードは2文字が非常に多い。

| 語 | FTS `MATCH` | 実際に含む発言 |
|---|---:|---:|
| 増税 | **0件** | 18件 |
| 憲法 | **0件** | 189件 |
| 年金 | **0件** | 733件 |

※ 2025年6月の1か月分での計測

**対策: 争点語の集計テーブルを別に持つ。**
運営者が管理する有限個の争点語リストについて、事前に発言IDを集計しておく。
これは企画書の「争点別スタンス比較」「キーワード頻度推移」と実装が重なるので追加コストは小さい。

本文はDBにあるので `LIKE '%増税%'` というフォールバックも一応使えるが、
全走査になるため sql.js-httpvfs 経由では現実的でない。

### 4-2. Wikidata に項目が無い議員がいる

現在9人（2,217発言 / 全体の0.4%）。うち6人は2026年初当選の新人で、
Wikidata の項目作成が追いついていないだけ。**恒久的な欠落ではない。**

対応方針は決まっている: **Wikidata ID は必須キーにせず補助キーにする。**
会議録側の情報だけで独自IDを振り、日次の再突合で項目ができた時点で自動的に紐づける。

### 4-3. 会派 → 政党の対応表は手動メンテが必要

新しい会派が出るたびに `data/party_map.json` への追記が要る。
`match_politicians.py` が未登録を警告するので気づけるが、自動化はされていない。

2026年だけで5件の新会派が登場した（`中道改革連合・無所属` `チームみらい` など）。
選挙のたびに増えると考えてよい。**月1時間の運用工数のうち、ここが主な消費先になる見込み。**

## 6. 決定済み事項（参照用）

判断を蒸し返す前に、まずここを見ること。根拠は `docs/PHASE0_FINDINGS.md` にある。

| 決定 | 理由 | 節 |
|---|---|---|
| 本文をDBに持つ（案A） | ハイライトが必須要件。contentless FTS5 では `snippet()` が使えない | §5.2 |
| 検索対象は議員の発言のみ | アプリの目的が「政治家を判断する材料の提供」だから | §5.3 |
| 参考人等もDBには保持する | 前後の文脈表示に使う。後から索引を足すだけで方針変更できる | §5.3 |
| DBは年ごとに分割 | 日次更新で変わるのは当年分だけ。CDNキャッシュも効く | §5.1 |
| DBは R2 に置く | Pages は25MiB/file、GitHub は100MB/file で置けない | §4 |
| 名寄せは読みが第一キー | 通称表記（あべ俊子→阿部俊子）は漢字では突合できない | §7 |
| 同姓同名は会派で分離 | 任期(P580)は付与率13.7%で使えない。院も大臣が他院に出るため不可 | §7 |
| 争点キーワードは会議録から | 外部ソース不要と実証。報道記事を使わない方針とも整合 | §10 |
| 予算は月1,000円 | ドメイン代のみ。全件AI処理は収まらない | — |
| 公開範囲を絞る必要はない | どの案でもR2無料枠に収まるため、段階公開の理由が消えた | §5.5 |
