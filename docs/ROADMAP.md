## 1. 争点語・頻出語を主機能に寄せる

方針の理由は [DECISIONS.md](DECISIONS.md) の「争点語・頻出語を主機能にする」。
**A（半角→全角）と B（2文字の全角ラテン）は実装済み。** 残りは C・D・E。
**どれも全年DBの作り直しが要らない**ので、公開したまま順に足していける。

### C. 頻出語レイヤー（`topic` とは別の第3の層）

**差別化の本体。** NDL は「語を入れたら発言が出る」まで。
**語の側から「いつ・どれだけ議論されたか」を見せる**機能は無い。

素材はほぼ揃っているので、見た目より安い:

- `build_topics.py` の `propose()` — 候補の抽出とランキングが既にある
- 同 `make_word_filter()` — **人名・役職・年号のフィルタが既にある**
- `topic_denylist.json` — 取りこぼしを1行で消す逃げ道も既にある

新規に書くのは出力形式だけ。**`data/dist/frequent.json`**（月×語の件数 + 分母）。

- **`topics.json` は82件のまま増やさない。** あれは編集方針、こちらは機械抽出。
  **ページ上でも「運営が選んだ争点語」と「機械抽出の頻出語」を明示的に分ける**
- **会派の内訳は上位N語にだけ付ける。** `topics.json` は 82語×20会派×64月で 278KB。
  同じ密度で500語やると約1.7MB。語だけなら500語×64月で数十KB。
  **分布を見たい語は限られる**ので上位だけで足りる（N は実測して決める）
- **DB再構築は不要。** ビルド時に Python で集計し、発言一覧は既存の索引に流す
- **分母（その月の発言数）で割る**

### D. 任意期間（月・会期）の抽出

**C を月粒度で持てば、ほぼタダ。** クライアントで月を足し合わせるだけ。

- **やってはいけない**: 任意期間をブラウザから `word_hit` / FTS で集計すること。
  年330万行の範囲集計は全走査になり、`ORDER BY date DESC` と同型の穴に落ちる
- **粒度は月に固定する。** 日付の自由入力は割に合わない
- 代わりに **`meeting.会期` を選べるようにする。**「第213回通常国会で急に増えた語」は
  政治的に意味のある区切りで、データは既にあり、コストは月の合算と変わらない

### E. 導線の入れ替え

トップを検索窓中心から**争点語・頻出語・急増語**中心に組み替え、検索は入口の1つに降ろす。
**既存機能は消さない。**「主にする」は情報の順序で表現する。

## 未解決の不具合

### Chrome でブラウザキャッシュが壊れると全ページが落ちる（原因は未特定）

2026-08-02 に実機で発生。**原因は分かっていないが、「一度壊れると永久に直らない」
性質のほうを消した**ので、公開の関門からは外した。**公開後もそのまま残っている。**

症状は全ページで `SQLite: file is not a database`。Chrome の通常ウィンドウだけで起き、
シークレット・Firefox・Vivaldi では正常。**Ctrl+Shift+R では直らず**、
キャッシュ削除で直る。Vivaldi も Chromium なので**エンジンではなくプロファイル固有**。

潰した容疑者: R2 の配信（無実。冷えたキャッシュでも 206 を 49ms で正しく返す）、
年DBの中身（無実。6年ともヘッダ正常・サイズ一致）、
`accept-ranges` が CORS で公開されていないこと（**原因ではない**。配布物を読むと
この値は警告を出すだけで取得の仕方を変えていない）。

対処として `immutable` を外し（再読み込みで治るようになった）、
やり直しに `&retry=` を足してURLを変えるようにした。
配信側を壊す再現（`POISON=1`）では6年すべてが自力で復旧するが、
**実機の再発はこれでは救えなかった**＝本物の壊れ方を再現できていない。

**再発したら、キャッシュを消す前にこれを見ること:**

1. **Console に `年のDBを読み直す` が出ているか** — 出ていれば再試行は走っている
   （＝別URLでも壊れたものが返る。キャッシュ以外の要因）
2. **Network タブの `kokkai-*.db` の Size 列。** `(disk cache)` ならブラウザキャッシュ由来。
   `retry=` 付きのURLが並んでいるかも見る
3. **`cache-control` に `immutable` が残っていないか**
