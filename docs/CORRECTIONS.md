# 訂正依頼への対応手順

所属政党の誤りを指摘されたときの手順。**公開後にいちばん来る訂正がこれ**なので、
調べ直さずに直せるようにしてある。

法務の前提は [SCOPE.md](SCOPE.md)「法務の最小セット」を参照。

---

## 所属政党を直す

### 1. 対象の議員を出す

```bash
python scripts/build_politicians.py --fix 浜田聡
```

名前・議員ID・Wikidata ID・読みのどれでも引ける。部分一致もする。
同姓同名で複数出たら、表示されたIDで指定し直す。

現在の所属が一覧で出て、**編集できる雛形が `data/party_overrides.json` に書き込まれる**。

```
浜田聡（はまださとし）  id=228  Q73111878
  URL に出る ID は 228。**この値は変えないこと**

  会派                   期間                        発言  現在の政党
  みんなの党                2021-02-10〜2022-06-08     232  NHKから国民を守る党
  ＮＨＫ党                 2022-10-20〜2025-05-20     134  NHKから国民を守る党
```

> **自動で決まった所属も雛形に出る。** 手入力リストに載っていない所属でも
> このコマンドなら直せる（候補が1つの会派は自動確定するので、そのままでは直せない）。

### 2. 値を直す

`data/party_overrides.json` の該当箇所を書き換える。

> **まとめて埋めるなら運営コンソール**（`python scripts/admin.py` の「政党」タブ）。
> 未入力の枠が上に来て、**その会派に所属しうる政党**（`data/party_map.json`）が
> ボタンで出る。書き換えるのは `party` だけで、枠そのものと `periods` には触らない
> （**期間で分かれている枠はここでは編集できない**。下の書式で直接直すこと）。

**全期間まとめて直す場合:**

```json
"みんなの党": {
  "_期間": "2021-02-10〜2022-06-08 / 232発言",
  "_候補": ["みんなの党", "NHKから国民を守る党"],
  "party": "NHKから国民を守る党"
}
```

**途中で政党が変わっていた場合** — `party` を `periods` に書き換える:

```json
"立憲民主・社民": {
  "_期間": "2021-01-14〜2024-06-11 / 1,596発言",
  "periods": [
    { "until": "2022-03-31", "party": "社会民主党" },
    { "party": "立憲民主党" }
  ]
}
```

**さらに細かく割る場合** — 区間を足すだけでよい:

```json
  "periods": [
    { "until": "2022-03-31", "party": "社会民主党" },
    { "until": "2023-03-31", "party": null },
    { "party": "立憲民主党" }
  ]
```

- `until` は**その日を含む**。次の区間は翌日から始まる
- 最後の区間に `until` は書かない
- **発言数と実際の開始日・終了日は実データから数え直される**（区切り方に合わせて自動）
- `party` を `null` にすれば「この期間はまだ分からない」を表現できる。
  その区間は政党不明として扱われ、`reports/party_todo.md` に戻ってくる
- 明示的に開始日を決めたいときは `"from": "2022-04-01"` を書く

**政党に所属していないと分かっている場合**は `"party": "無所属"`。
`null`（＝特定できていない）とは意味が違う。

**訂正の経緯を残す**なら `_note` を足す。自由記述で、再実行しても消えない:

```json
"Q11521820": {
  "_name": "杉尾秀哉（すぎおひでや）",
  "_note": "2026-08-01 訂正依頼 #12。本人事務所より社民党→立憲民主党の時期の指摘",
  ...
}
```

### 3. 反映する

```bash
python scripts/build_politicians.py     # 議員マスタを作り直す
python scripts/build_db.py --split      # 期間DBに入れる（半期12本）
```

`build_politicians.py` は**冪等**（同じ入力なら何度回しても同じ結果）。
実行するたびに以下を確認してくれる:

| 警告 | 意味 |
|---|---|
| `「X」は会派の候補に無い` | 打ち間違いか、`party_map.json` の更新漏れ |
| `「X」は party_map.json のどこにも無い` | 政党名の打ち間違いの可能性が高い |
| `区間の合計 N件が全体 M件と合わない` | **区間に隙間がある。発言が落ちている** |
| `区間 A〜B に発言が無い` | その区間の指定が実データと合っていない |

### 4. 直ったか確かめる

```bash
python scripts/build_politicians.py --fix 浜田聡
```

もう一度 `--fix` を叩けば、直った後の状態が一覧で出る。

## 議員IDは絶対に変えない

`data/politician_ids.json` は議員ID の台帳で、**IDはURLに出る**（`/politician/228`）。
作り直すと公開済みのリンクが全部壊れる。

- **このファイルは必ずコミットする**
- 議員が消えても行を消さない（追記だけが安全な操作）
- Wikidata に項目が無かった議員に後からQIDが付いても、IDは維持される
  （台帳が `local:表記:読み` と QID の両方を同じIDに紐づける）

同姓同名は Wikidata ID で分かれる。**未マッチの同姓同名だけは分離できない**ので、
`reports/politicians.md` に警告が出る。

---

## 名前の表記を直したい場合

`politician.name` は**会議録での代表表記**（いちばん多く使われた表記）を機械的に採っている。
「あべ俊子」のような通称で通っている議員がいるため、Wikidata の表記では上書きしていない。

これを変える仕組みは今のところ無い。必要になったら
`scripts/build_politicians.py` の `build_records()` に上書きの口を足すこと。

---

## コミットするファイル

`data/` は基本 `.gitignore` 済みだが、**手書きの資産は必ずコミットする**。
生成物ではないので、失うと作り直しになる。

| ファイル | 失うとどうなるか |
|---|---|
| `data/politician_ids.json` | **公開後はURLが全部変わる** |
| `data/party_overrides.json` | 手入力した政党（約150件）が消える |
| `data/party_map.json` | 会派→政党の対応が消え、同姓同名の分離も弱くなる |
| `data/topics.json` | 争点語リスト（編集方針そのもの）が消える |
| `data/topic_denylist.json` | トレンドから外した語が復活する |
